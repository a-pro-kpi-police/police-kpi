# KPI — Отдел полиции (KPI Dashboard for Police Department)

Веб-приложение для оценки эффективности сотрудников полиции. Сотрудники
вносят записи о выполненной работе (KPI), а начальник отдела подтверждает или
отклоняет их. Дашборд показывает агрегированные показатели эффективности.

- **Backend:** Python (FastAPI + SQLAlchemy + SQLite)
- **Frontend:** React (Vite) + Recharts
- **Языки интерфейса:** Русский / Қазақша (переключатель RU / KZ)
- **Роли:** `officer` (вносит записи) и `head` (подтверждает)

## Организация backend

- `main.py` — создание FastAPI-приложения, middleware и подключение маршрутов
- `routers/` — HTTP API по областям: auth, catalog, targets, entries, dashboard
- `services/` — расчёты целей, преобразование записей и агрегаты дашборда
- `models.py` / `schemas.py` — модели базы данных и API-схемы
- `kpi_catalog.csv` — активный справочник KPI с единицами измерения из рабочей таблицы
- `seed.py` — начальное заполнение и безопасное обновление справочника KPI

## Структура колонок записи KPI
Дата · Месяц · ФИО сотрудника · Код KPI · Показатель · Блок · НПА/статья ·
Источник · Количество · Балл за 1 ед. · Коэфф. участка · Сырые баллы · Итоговые
баллы · Статус · Комментарии

Расчёт за месяц:

1. В статистике сохраняется полное количество подтверждённых фактов.
2. В KPI засчитывается `MIN(количество, месячный лимит)`.
3. Доля массовых показателей считается от положительных баллов после лимитов.
4. При доле свыше 40% применяется коэффициент `0,85`, свыше 60% — `0,70`.
5. Критический показатель обнуляет результат сотрудника за месяц.
6. Эффективность сравнивается с месячной нормой 100 баллов, а не с
   назначенными целями.

## Импорт месячной таблицы

Docker использует отдельную базу `/data/kpi_july_2026.db`. Предыдущая
`/data/kpi.db` не удаляется и не перезаписывается.

При первом запуске в новую базу импортируется снимок
`backend/import_data/monthly_kpi_2026_07.csv`:

- 152 сотрудника;
- 134 показателя KPI;
- 20 368 явных значений сотрудник × KPI, включая нулевые;
- импортированные строки датируются 1–29 июля 2026 года.

Повторно получить CSV из исходного Numbers-файла можно на macOS:

```bash
osascript -l JavaScript scripts/export_monthly_numbers.js \
  ./KPI_*.numbers \
  backend/import_data/monthly_kpi_2026_07.csv \
  backend/kpi_catalog.csv
```

## Запуск

Требуется Docker с поддержкой `docker compose`.

### 1. Все сервисы
```bash
docker compose up --build
```
Откройте http://localhost:5173.

### 2. Только backend
```bash
docker compose up --build backend
```
Backend доступен на http://localhost:8000.

### 3. Frontend + backend
```bash
docker compose up --build frontend
```
Vite проксирует `/api` на backend-контейнер.

При первом запуске база создаётся и заполняется примерами автоматически.
Данные SQLite хранятся в Docker volume `backend_data`.

### Полезные команды
```bash
docker compose down          # остановить сервисы
docker compose down -v       # остановить и удалить volumes (сбросить БД)
docker compose logs -f       # смотреть логи
```

## API
- `POST /api/auth/login` — вход (form: username, password)
- `GET  /api/auth/me` — текущий пользователь
- `GET  /api/catalog` — справочник показателей KPI
- `GET/PUT /api/targets` — получить/назначить цели отдельному сотруднику
- `GET/PUT /api/group-targets` — получить/назначить цели всем сотрудникам участка
- `GET  /api/entries` — записи (сотрудник видит свои, начальник — все)
- `POST /api/entries` — создать запись (сотрудник для себя, начальник для выбранного сотрудника)
- `PATCH /api/entries/{id}/status` — подтвердить/отклонить (начальник)
- `GET  /api/dashboard` — агрегаты для дашборда
- `GET  /api/officers` — рейтинг (через /dashboard)
